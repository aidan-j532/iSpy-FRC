# iSpy FRC

iSpy is a computer vision pipeline for FIRST Robotics Competition robots. It watches a camera, detects objects on the field, transforms those detections into field-relative coordinates, and sends them to the robot over NetworkTables. The project also includes a local web UI for camera setup, model management, health checks, logging, rollback, and calibration.

This is the practical path for a team that wants a self-contained vision solution instead of a pile of unrelated tools. It is meant to sit on a small Linux board or dev machine and do one job well: take a camera stream and turn it into useful robot data.

## What it does

The typical flow is straightforward:

1. a camera sees the field
2. a YOLO model detects game pieces or objects
3. the code converts pixel coordinates into real-world field coordinates
4. the result is published to the robot over NetworkTables
5. the robot reacts to the target information in real time

The system can also produce live annotated video, run local health checks, record sessions for rollback, and optimize model formats for specific hardware.

## Good target hardware

The project is built around real deployment hardware and practical FRC constraints:

- Orange Pi 5 / 5 Pro with Rockchip NPU is the recommended board
- ARM64 Linux boards can run the same stack with TFLite or other compatible backends
- x86_64 Linux machines work well for local dev and ONNX/OpenVINO setups
- macOS on Apple Silicon can use CoreML
- Windows can be used for ONNX-based setups

This is one of those projects where the hardware really matters, because the backend and model format are selected based on what the machine supports.

## The normal setup path

Most users follow a simple pattern:

```bash
git clone https://github.com/aidan-j532/iSpy-FRC
cd iSpy-FRC
chmod +x install.sh
./install.sh
ispy-boot -f
ispy-run
```

Then they open the web UI at:

```text
http://<machine-ip>:5000
```

That gets them to the dashboard and camera config page, which is where most actual setup work happens.

## This docs set

The rest of the docs are organized around the real workflow a new user actually needs:

- install the software
- configure the first camera
- connect the model
- tune the calibration
- run the pipeline
- monitor health and logs
- handle networking and FRC output
- debug problems and recover cleanly

If you are starting from zero, read the install guide first and then move into the camera and model setup pages. The project is meant to be usable without reading every line of code, but it does assume you are willing to do a little practical tuning once the machine is running.

## Important distinction

The names are a little easy to confuse at first:

- `ispy-boot` sets up generated state and does the first-run initialization
- `ispy-run` starts the actual camera + detection loop
- the web UI is the main place to manage cameras, models, and live settings

That separation matters. Boot is for setup; run is for live operation.
