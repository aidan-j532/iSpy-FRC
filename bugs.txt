P1 — RKNN unit tests hit REAL hardware with garbage data during every boot
═══════════════════════════════════════════════════════════════════
iSpy/validations/unit_tests.py fakes rknnlite via sys.modules substitution at
module import time, then imports GenericYolo. This only works if unit_tests.py is
the FIRST thing to import iSpy.vision.genericYolo in the process. It isn't:
boot.py's metadata-generation step (setup_files() -> metadata_from_pt() for each
bundled .pt) triggers `from iSpy.vision.genericYolo import torch_load`, which
executes genericYolo.py's module-level `from rknnlite.api import RKNNLite` for
real — and on this hardware, real rknnlite IS installed, so RKNN_FOUND=True and
genericYolo.RKNNLite is bound to the real class before unit_tests.py's fakery ever
runs. Python's module cache means unit_tests.py's later `sys.modules["rknnlite"]
= fake` has zero effect on the already-imported genericYolo module.

Result, visible in the log: test_loads_rknn_when_rknnlite_present() constructs a
GenericYolo from a 4KB file of zero bytes with a .rknn extension, which goes
through the REAL RKNNLite().load_rknn() / init_runtime() against real NPU driver
calls, and blows up with `RKNN_ERR_MODEL_INVALID` — not a mocked, deterministic,
hardware-independent result like the test intends. This is a test-isolation bug
that (a) makes the RKNN unit tests meaningless on any machine with real rknnlite
installed, (b) spams real driver error output into every boot log, and (c) was
being silently swallowed by the P1 bug above so nobody noticed it was broken.

FIX — pick one:
1. (Preferred) Make the fake unconditional and import-order-independent: instead
   of monkeypatching sys.modules and hoping nothing imported the real module first,
   have unit_tests.py patch `iSpy.vision.genericYolo.RKNNLite` directly (the
   already-bound symbol) via `unittest.mock.patch.object` in a setUp/context
   manager scoped to the RKNN test class, regardless of what was imported when.
2. Alternatively, force genericYolo to be freshly imported under the fake
   environment by removing it (and rknnlite/rknnlite.api) from sys.modules before
   the fakes are installed, then re-importing — fragile, avoid if (1) works.

Also fix GenericYolo's exception handling while you're in here: `RKNNLite.init_runtime()`
can raise a bare Exception from the native layer (as seen in the log — not a
non-zero return code, an actual raised Exception), but genericYolo.py only checks
`if self.model.init_runtime(...) != 0: raise ValueError(...)`. A raised exception
from the driver bypasses that check and propagates a raw, unhelpful native
exception instead of iSpy's own error type. Wrap the init_runtime() and load_rknn()
calls in try/except and re-raise as ValueError with the model path in the message,
consistent with the rest of that constructor.

ACCEPTANCE: run the unit test suite standalone (`python -m iSpy.validations.ez` or
equivalent) on the same board that showed this bug, confirm no real RKNN driver
output appears in the test run, and the RKNN tests pass using genuinely fake calls.

P2 — yolo_pt.py shim can't load the two shipped default models
═══════════════════════════════════════════════════════════════════
Log shows both bundled non-basic-detect models fail metadata generation:
    _default_pose.pt        -> Can't get attribute 'PoseModel' on ultralytics.nn.tasks

iSpy/vision/yolo_pt.py's shim only registers Conv, C2f, SPPF, Bottleneck, Concat,

    _default_v26_detect_for_fuel.pt

metadata_from_pt() currently catches this and logs a warning, so boot doesn't
crash — but this is not just a metadata problem. fill_missing_config() falls back
to inspect_model() -> _inspect_ultralytics() -> load_yolo_pt() on ANY load attempt
when no metadata sidecar exists, which hits the exact same missing-attribute
failure at actual inference time, not just at boot. In other words: right now,
on this hardware, the shipped pose model and the shipped v26/fuel detect model
are BOTH completely non-functional — any camera configured to use either one will
fail to construct GenericYolo entirely. Only _default_detect.pt (plain YOLOv8
detect) works.

This is a big gap, not a nice-to-have. Two options, pick based on which models
are actually meant to ship:

Option A — if _default_pose.pt and _default_v26_detect_for_fuel.pt are meant to
keep shipping, the shim needs real architecture support added:
  - PoseModel: register as an alias/subclass marker (mirror DetectionModel's
    approach) and extend Detect (or add a Pose head class) with the keypoint
    branch — cv4 conv stack producing num_keypoints * keypoint_dims channels,
    decoded the same way GenericYolo._parse_raw_pose already expects
    (features_first -> keypoints after the score columns). Check what keypoint
    head shape the actual checkpoint's state_dict expects before guessing at
    the module structure — load the checkpoint's raw state_dict keys (without
    unpickling the model, just `torch.load(..., weights_only=True)` won't work
    since it's not a weights-only checkpoint, so inspect via `zipfile` on the
    .pt to read the pickle's referenced class paths) to confirm the exact
    module names/shapes needed instead of guessing.
  - C3k2/C3k: implement the YOLOv11-style block (a C2f variant with a
    configurable inner block — C3k when a flag is set, otherwise a plain
    Bottleneck) under ultralytics.nn.modules.block in the shim namespace.

Option B — if these are legacy/test assets that shouldn't be bundled as
"_default_*" anymore, remove them from iSpy/assets/ and update boot.py's
staging step + default_vision_model()'s fallback logic (iSpyConfig.py) so
nothing points at a pose or v26 model by default. Confirm with Aidan which
of these is actually correct before touching the shim — this is a scope
decision, not a pure bug fix, and guessing wrong wastes real implementation
work on either the shim or the asset cleanup.

NEW P1 — exception narrowing in ObjectDetectionPipeline hides real failures

iSpy/vision/pipelines/object_detection.py, __init__():

a camera at a .pt the shim can't parse) and confirming you get a clean warning, not
